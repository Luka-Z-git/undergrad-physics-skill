# 可选模式：学生诊断 (Tutoring Mode)

本模式是可选分支，只在用户明确要求检查或诊断其作答时进入；默认主流程仍是模板 A 完整解题。

## 触发

用户消息含以下意图之一即进入本模式：

- "诊断"
- "看看我写的"
- "帮我检查"
- "我哪里错了"
- "这步对吗"
- "看我卡在哪"

只发题目、无检查意图时，不进入本模式，走 SKILL.md 主流程。

## 流程

1. **获取进度**：学生未贴出作答时，要一句："贴出你目前的作答，至少包含你已写出的方法/方程/推导/答案，并说明卡在哪一步（可选）。"
2. **完整性检查**：四要素为方法、方程、推导、答案。
   - 不完整：直接指出缺哪一项，并给出下一步具体该写什么（一句，不展开完整解答）。
   - 完整：进入核验。
3. **核验与定位**：用 F 量纲 / L 极限特例 / B 回代 / C 守恒量（适用时）逐条核验学生结果；定位第一个错误（步骤 + 表达式 + 错因）；映射到对应概念误区（可引用 `modules/error_prevention.md`）；给出正确写法与原因。
4. **确认理解**：给出一道需要学生回答的短问题，确认其理解而非照抄。
5. **循环**：学生改完再发一次，重复第 2–4 步；连续两轮仍 FAIL 时，建议切回模板 A 完整解答或 `modules/review_engine.md` 独立复核。

## 输出模板（模板 E）

输出严格按 `modules/output_templates.md` 模板 E 的六字段与顺序执行；字段定义不在此重复。

## 纪律

- 直接指出缺项与错误，不做提示分级。
- 诊断模式不自动展开模板 A 完整答案；学生明确要完整答案时才切回主流程。
- 不引用 `examples/` 完整例题代答。
- 核验纪律沿用 `modules/verification_engine.md`。
- 范围外题目（热学、光学、统计物理、研究生内容）如实说明不适用，不硬解。

## 确认题质量标准

确认题是诊断模式的核心教学工具——一道好的确认题能检验学生是否真正理解了概念，而非仅仅记住了结论。**出题原则**：

1. 必须能用 1–3 句话回答，但回答需要**经过推理**（不能从原题答案直接抄）。
2. 优先让学生**换个视角**看同一个物理（反事实、极限、对比、推广）。
3. 避免是非题（"对吗？"）和纯记忆题（"记住 X=Y"）。

良好/不良对照表与分场景示例见 `examples/tutoring_diagnosis.md` 末尾的「确认题质量校准参考」表。
